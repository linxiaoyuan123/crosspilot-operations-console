# 实施交付工作流指南

这份指南说明如何用 DeployMate 完成一次典型的客户系统实施。界面默认包含一个华南零售 ERP 门店上线项目，可以直接基于它操作。

## 1. 建立实施项目

进入“实施项目”，创建客户、产品、环境、负责人和计划上线日期。项目建立后会自动生成 8 个标准阶段任务：

`需求确认 → 环境预检 → 安装部署 → 数据核验 → 联调测试 → 用户培训 → 项目验收 → 上线复盘`

阶段任务不是静态说明。现场完成后应填写状态、负责人、日期和证据，例如检查截图名称、备份文件、客户确认记录或整改说明。

## 2. 执行环境预检

进入“环境预检”，选择当前项目后可以执行：

- Windows/Linux 主机信息、CPU、内存和磁盘检查
- DNS 解析
- TCP 端口连通性
- HTTP/WEB 服务响应
- Ping 时延与丢包
- 本应用健康检查

对于客户有明确要求的项目，可以填写内存上限、磁盘最低剩余空间和 CPU 负载期望值。检查完成后记录实际值和整改证据，并将失败项转成项目阻塞任务或问题单。

## 3. 核验交付数据

进入“数据库交付”：

1. 新建 SQLite、MySQL 或 SQL Server 连接。
2. 执行连接测试并读取表结构。
3. 用只读 SQL 验证关键数据。
4. 将常用检查保存为数据校验模板。
5. 执行模板并记录期望值、实际值和结论。
6. 对需要交付的查询结果或数据表导出 CSV。

需要准备备份或恢复时，点击“备份恢复方案”，选择操作并填写备份文件路径。系统只生成 SQLite、MySQL 或 SQL Server 的人工执行命令，并保存生成状态，不会代替工程师执行恢复。
推荐至少检查主数据完整性、业务单据状态、接口同步记录、重复数据和关键金额汇总。密码只在当前请求中使用，不会写入数据库或导出文件。

危险 SQL 默认不能执行。确实需要维护操作时，先开启写操作，再按照界面要求输入确认短语；生产环境仍应优先使用客户批准的脚本和变更流程。

## 4. 处理客户问题

进入“技术支持”，新建问题单并记录：

- 客户和项目
- 问题现象和影响范围
- 优先级和当前状态
- 诊断证据
- 处理过程
- 根本原因
- 解决方案
- 后续跟进

每次联系客户、执行诊断、完成数据校验或调整状态，都可在问题时间线中追加记录。问题解决后填写解决方案，再点击“沉淀知识库”，系统会保留项目关联、原因和处理步骤。

## 5. 完成培训与验收

进入“培训验收”，按四类事项维护交付清单：

- 账号与角色：用户、权限、组织关系和初始密码交付方式。
- 用户培训：签到、培训材料和关键岗位确认。
- 项目验收：功能确认、验收项、签字和日期。
- 交付文档：部署记录、数据核验、问题清单和运维说明。

勾选完成项并填写证据后，可以生成验收报告。遗留问题应明确负责人、处理计划和期望完成时间，不应只写“后续处理”。

## 6. 生成交付报告

项目报告和培训验收报告支持：

- HTML：浏览器打开、打印或另存为 PDF。
- Markdown：便于放入项目文档或知识库。
- CSV：便于交给客户或继续整理。

导出前检查报告是否包含正确的项目、任务状态、检查结论、问题记录和验收事项。系统会自动清理密码、令牌和连接密钥等敏感字段，但仍建议在交付前人工复核服务器地址、账号和客户信息。

## 7. 上线复盘与知识沉淀

上线后更新“上线复盘”阶段，记录：

- 上线范围与完成时间
- 实际发生的问题和解决情况
- 未关闭事项及责任人
- 客户反馈
- 可复用的检查、SQL 和排障步骤

已解决问题转成知识文章后，可按标题、分类、现象或解决方案搜索，用于下一次同类项目交付。

## 本地数据说明

默认应用数据保存在 `data/deploymate.db`，内置 ERP 演示库保存在 `data/demo-erp.db`。删除这些文件会重新初始化演示数据。准备真实客户项目时，建议先备份 `data/` 目录，并避免把真实客户敏感数据提交到 Git 仓库。
